\section{Measurement Platform Architecture}
\label{sec:platform}

Automated web privacy measurement platforms frequently succumb to the \textbf{Emulation Fallacy}~\cite{cassel2022omnicrawl}: headless automation frameworks (e.g., Puppeteer, vanilla Selenium) leak telltale execution artifacts (\texttt{navigator.webdriver}, missing rendering contexts, anomalous clock skews)~\cite{vastel2020fp}. 
Commercial ad-fraud filters detect these anomalies and silently drop bid requests or serve synthetic filler ads, causing crawlers to record artificial auction artifacts~\cite{ahmad2020apophanies, demir2022reproducibility}. 
To ensure experimental fidelity, we designed and deployed a hardened, distributed measurement cluster running native Linux binaries over virtual displays.

\subsection{Cluster Execution \& Environment Hardening}
\label{subsec:cluster_hardening}

\paragraph{Native Execution on Virtual Framebuffers}
Workloads are parallelized across dedicated cluster nodes via Docker containers implementing a sidecar proxy pattern. Instead of relying on Chromium's \texttt{--headless=new} or Gecko's \texttt{-headless} flags, both of which bypass standard graphics pipelines and alert anti-bot heuristics~\cite{cassel2022omnicrawl, vastel2020fp}, the platform executes uninstrumented native Linux binaries (Chrome, Firefox, Brave) against isolated X Virtual Framebuffer (\texttt{Xvfb}) display servers operating at display \texttt{:99} ($1920 \times 1080 \times 24$, 24-bit TrueColor depth).

\paragraph{Mesa Software Rasterization}
Cluster worker nodes feature heterogeneous physical GPUs, which introduce divergent hardware entropy into WebGL and 2D canvas draw operations~\cite{mowery2012pixel, cao2017cross}. 
We eliminate physical GPU confounding by forcing Mesa software rasterization across all containers via environment overrides. 
This forces Chromium and Gecko rendering engines to execute all graphics operations via identical CPU-based rasterization logic (\path{swrast}/\path{llvmpipe}), ensuring baseline visual determinism across cluster workers. 
Furthermore, we unset session D-Bus variables and generate container-isolated machine identifiers to prevent processes from blocking on desktop keyring daemons.

\subsection{Network Interception \& Proxy Stealth}
\label{subsec:proxy_stealth}

Network interception is managed via an upstream \texttt{mitmproxy} sidecar instance incorporating specific stealth countermeasures:
\begin{itemize}
    \item \textbf{Dual-Tier CA Injection:} To inspect TLS flows without launching browsers under insecure bypass flags (which alert commercial crawlers~\cite{ahmad2020apophanies}), our platform installs an ephemeral root CA into both the host operating system trust store and the user NSS SQLite databases;
    \item \textbf{Transport-Layer Fingerprint Evasion:} Python-based proxy engines emit distinctive HTTP/2 frame multiplexing sequences that commercial Web Application Firewalls (Cloudflare, Akamai) classify as crawler traffic~\cite{ahmad2020apophanies, vastel2020fp};
    we enforce an HTTP/1.1 transport downgrade on upstream pipelines to neutralize proxy-specific TLS/H2 fingerprinting; 
    \item \textbf{Causal Anti-Cache Enforcement:} To guarantee that post-intervention measurements represent genuine live network transactions rather than disk cache hits, the proxy strips conditional validation headers (\texttt{If-Modified-Since}, \texttt{If-None-Match})~\cite{rfc7231, rfc9110}, forcing origin servers to return explicit HTTP 200 responses;
\end{itemize}

\subsection{3-Tier Hybrid CMP Auto-Consent Engine}
\label{subsec:cmp_engine}

Under European GDPR and ePrivacy frameworks, programmatic header bidding auctions stall until user consent is recorded~\cite{papadogiannakis2021user}. Unhandled Consent Management Platform (CMP) dialogs freeze \texttt{Prebid.js} bid loops, resulting in complete auction drops. 
To resolve this, we engineered an asynchronous 3-tier hybrid consent engine:
\begin{enumerate}
    \item \textbf{Tier 1 (API-First Settlement):} Inspects the global \texttt{window} context and directly triggers official framework handlers (\path{OneTrust.AllowAll()}, \path{Didomi.setUserAgreeToAll()}, or \path{Cookiebot.dialog.submit()});
    \item \textbf{Tier 2 (Targeted CSS Mutators):} Dispatches synthetic mouse events to common consent selectors (\texttt{\#onetrust-\allowbreak{}accept-\allowbreak{}btn-\allowbreak{}handler}, \texttt{.cmp-\allowbreak{}agree-\allowbreak{}all}, or \texttt{button[id*="consent"]}), then performs programmatic wheel scrolling;
    \item \textbf{Tier 3 (Heuristic DOM Regex Traversal):} Recursively traverses the DOM and consent \texttt{iframe} scopes to match affirmative multilingual strings (English, Portuguese: e.g., \path{/(Accept All|Aceitar Todos|Aceptar Todo)/i}) bounded strictly by character length ($2 \le \text{length} < 35$).
\end{enumerate}

\subsection{Atomic Profile Sanitization}
\label{subsec:profile_sanitization}

In preliminary trials, standard profile cloning leaked persistent identifiers across experimental phases: Blink-based browsers cache session descriptors within LevelDB stores, HSTS supercookies, and Web Storage~\cite{acar2014web, whatwg_webstorage}, producing artificial $0.0\%$ bid shifts. 
To enforce complete storage clearance while preserving browser defense flags, we designed an \textbf{Atomic Profile Sanitizer} that programmatically strips persistent transaction stores while maintaining client configuration integrity (detailed in Appendix~\ref{sec:appendix_sanitizer}).
